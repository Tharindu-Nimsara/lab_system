# Medical Laboratory Management System — Implementation Instructions (Java Edition)

**Companion to:** Implementation Plan v2.0 · This document is the hands-on "how to build it" guide for the **Spring Boot + PostgreSQL + React** stack: environment setup, project scaffolding, database migrations, security configuration, and a step-by-step build order with commands and code you can follow directly.

## Part 1 — Environment Setup


**Package-by-feature, not package-by-layer.** Each business module (patient, billing, results…) owns its controller, service, repository, and entity in one package. This keeps related code together and makes future extraction trivial.

### 2.3 The Flyway schema

`src/main/resources/db/migration/V1__init.sql` — this is the entire database, versioned in Git:

```sql
CREATE TABLE branches (
    id         BIGSERIAL PRIMARY KEY,
    name       TEXT NOT NULL,
    address    TEXT,
    phone      TEXT,
    is_active  BOOLEAN NOT NULL DEFAULT TRUE
);

CREATE TABLE users (
    id            BIGSERIAL PRIMARY KEY,
    branch_id     BIGINT NOT NULL REFERENCES branches(id),
    name          TEXT NOT NULL,
    email         TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL,
    role          TEXT NOT NULL CHECK (role IN ('ADMIN','RECEPTIONIST','LAB_STAFF','MARKETING')),
    is_active     BOOLEAN NOT NULL DEFAULT TRUE,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE patients (
    id               BIGSERIAL PRIMARY KEY,
    patient_no       TEXT NOT NULL UNIQUE,        -- e.g. P-000123
    name             TEXT NOT NULL,
    nic_or_id        TEXT,
    dob              DATE,
    gender           TEXT,
    phone            TEXT NOT NULL,               -- primary lookup key
    email            TEXT,
    address          TEXT,
    consent_email    BOOLEAN NOT NULL DEFAULT FALSE,
    consent_whatsapp BOOLEAN NOT NULL DEFAULT FALSE,
    created_at       TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_patients_phone ON patients(phone);
CREATE INDEX idx_patients_name  ON patients(name);

CREATE TABLE test_templates (
    id     BIGSERIAL PRIMARY KEY,
    name   TEXT NOT NULL,
    -- example: [{"key":"glucose","label":"Fasting Glucose","unit":"mg/dL",
    --            "refLow":70,"refHigh":100,"type":"number"}]
    fields JSONB NOT NULL
);

CREATE TABLE tests (
    id            BIGSERIAL PRIMARY KEY,
    code          TEXT NOT NULL UNIQUE,           -- e.g. FBS, LIPID
    name          TEXT NOT NULL,
    category      TEXT NOT NULL,                  -- Biochemistry, Hematology, ...
    price         NUMERIC(10,2) NOT NULL,
    specimen_type TEXT,
    template_id   BIGINT NOT NULL REFERENCES test_templates(id),
    is_active     BOOLEAN NOT NULL DEFAULT TRUE
);

CREATE TABLE invoices (
    id             BIGSERIAL PRIMARY KEY,
    invoice_no     TEXT NOT NULL UNIQUE,          -- e.g. INV-20260718-0042
    branch_id      BIGINT NOT NULL REFERENCES branches(id),
    patient_id     BIGINT NOT NULL REFERENCES patients(id),
    created_by     BIGINT NOT NULL REFERENCES users(id),
    subtotal       NUMERIC(10,2) NOT NULL,
    discount       NUMERIC(10,2) NOT NULL DEFAULT 0,
    total          NUMERIC(10,2) NOT NULL,
    payment_method TEXT NOT NULL,                 -- CASH | CARD
    status         TEXT NOT NULL DEFAULT 'PAID',  -- PAID | VOID
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_invoices_created_at ON invoices(created_at);

CREATE TABLE invoice_items (
    id            BIGSERIAL PRIMARY KEY,
    invoice_id    BIGINT NOT NULL REFERENCES invoices(id),
    test_id       BIGINT NOT NULL REFERENCES tests(id),
    price_at_sale NUMERIC(10,2) NOT NULL
);

CREATE TABLE orders (
    id                  BIGSERIAL PRIMARY KEY,
    invoice_item_id     BIGINT NOT NULL UNIQUE REFERENCES invoice_items(id),
    status              TEXT NOT NULL DEFAULT 'PENDING'
        CHECK (status IN ('PENDING','COLLECTED','IN_PROGRESS','COMPLETED','VERIFIED')),
    sample_collected_at TIMESTAMPTZ,
    result_entered_by   BIGINT REFERENCES users(id),
    verified_by         BIGINT REFERENCES users(id),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE results (
    id         BIGSERIAL PRIMARY KEY,
    order_id   BIGINT NOT NULL UNIQUE REFERENCES orders(id),
    "values"   JSONB NOT NULL,                    -- {"glucose": 126}
    flags      JSONB,                             -- {"glucose": "H"}
    entered_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE reports (
    id               BIGSERIAL PRIMARY KEY,
    patient_id       BIGINT NOT NULL REFERENCES patients(id),
    invoice_id       BIGINT NOT NULL UNIQUE REFERENCES invoices(id),
    pdf_path         TEXT,
    finalized_at     TIMESTAMPTZ,
    sent_email_at    TIMESTAMPTZ,
    sent_whatsapp_at TIMESTAMPTZ
);

CREATE TABLE expenses (
    id           BIGSERIAL PRIMARY KEY,
    branch_id    BIGINT NOT NULL REFERENCES branches(id),
    category     TEXT NOT NULL,                   -- SALARY|KITS|EQUIPMENT|UTILITY|OTHER
    description  TEXT,
    amount       NUMERIC(10,2) NOT NULL,
    expense_date DATE NOT NULL,
    entered_by   BIGINT NOT NULL REFERENCES users(id)
);

CREATE TABLE audit_logs (
    id         BIGSERIAL PRIMARY KEY,
    user_id    BIGINT NOT NULL REFERENCES users(id),
    action     TEXT NOT NULL,                     -- VIEW|CREATE|UPDATE|VOID|LOGIN ...
    entity     TEXT NOT NULL,                     -- Patient|Invoice|Result ...
    entity_id  BIGINT,
    details    JSONB,
    ip         TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_audit_entity ON audit_logs(entity, entity_id);
```

Start the app (`./mvnw spring-boot:run`) — Flyway creates every table automatically. Verify with `psql` or IntelliJ's database panel. **All future schema changes are new files** (`V2__add_x.sql`, `V3__...`) — never edit an applied migration.

### 2.4 Example entity + repository (the pattern for every module)

`patient/Patient.java`:

```java
@Entity @Table(name = "patients")
@Getter @Setter @NoArgsConstructor
public class Patient {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "patient_no", nullable = false, unique = true)
    private String patientNo;

    @Column(nullable = false) private String name;
    @Column(name = "nic_or_id") private String nicOrId;
    private LocalDate dob;
    private String gender;
    @Column(nullable = false) private String phone;
    private String email;
    private String address;
    @Column(name = "consent_email")    private boolean consentEmail;
    @Column(name = "consent_whatsapp") private boolean consentWhatsapp;
    @Column(name = "created_at", insertable = false, updatable = false)
    private OffsetDateTime createdAt;
}
```

`patient/PatientRepository.java`:

```java
public interface PatientRepository extends JpaRepository<Patient, Long> {
    @Query("""
        SELECT p FROM Patient p
        WHERE p.phone LIKE CONCAT('%', :q, '%')
           OR LOWER(p.name) LIKE LOWER(CONCAT('%', :q, '%'))
        ORDER BY p.createdAt DESC
        """)
    List<Patient> search(@Param("q") String query, Pageable page);
}
```

For JSONB columns (templates, results), use Hypersistence Utils:

```java
@Type(JsonType.class)
@Column(columnDefinition = "jsonb")
private JsonNode fields;    // com.fasterxml.jackson.databind.JsonNode
```

### 2.5 Security configuration

`config/SecurityConfig.java` — session login, BCrypt, role rules:

```java
@Configuration
@EnableWebSecurity
@EnableMethodSecurity          // enables @PreAuthorize on service/controller methods
public class SecurityConfig {

    @Bean
    PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }

    @Bean
    SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
          .cors(Customizer.withDefaults())
          .csrf(csrf -> csrf.csrfTokenRepository(
                CookieCsrfTokenRepository.withHttpOnlyFalse()))
          .authorizeHttpRequests(auth -> auth
              .requestMatchers("/api/auth/login", "/actuator/health").permitAll()
              .requestMatchers("/api/admin/**").hasRole("ADMIN")
              .requestMatchers("/api/finance/**").hasAnyRole("ADMIN")
              .requestMatchers("/api/orders/**", "/api/results/**")
                  .hasAnyRole("ADMIN", "LAB_STAFF")
              .requestMatchers("/api/invoices/**", "/api/patients/**")
                  .hasAnyRole("ADMIN", "RECEPTIONIST")
              .anyRequest().authenticated())
          .formLogin(AbstractHttpConfigurer::disable)
          .httpBasic(AbstractHttpConfigurer::disable);
        return http.build();
    }
}
```

Login endpoint: load the user by email, check `passwordEncoder.matches(raw, user.getPasswordHash())`, put an authenticated token in the `SecurityContext`, and write an `audit_logs` row. Seed the first admin with a `CommandLineRunner` bean that creates one if the users table is empty.

**Rule to follow everywhere:** authorization lives in the filter rules and `@PreAuthorize` annotations on the server. The frontend hiding a button is cosmetic, never security.

### 2.6 Global error handling

One `@RestControllerAdvice` class that maps `MethodArgumentNotValidException` → 400 with field errors, `EntityNotFoundException` → 404, `AccessDeniedException` → 403, and everything else → 500 with a logged stack trace and a generic message (never leak internals to the client).

API helper that carries the session cookie and CSRF token — `client/src/api/client.ts`:

```ts
function getCsrf(): string {
  return document.cookie.match(/XSRF-TOKEN=([^;]+)/)?.[1] ?? "";
}

export async function api<T>(path: string, options: RequestInit = {}): Promise<T> {
  const res = await fetch(`http://localhost:4000/api${path}`, {
    credentials: "include",
    headers: {
      "Content-Type": "application/json",
      "X-XSRF-TOKEN": getCsrf(),
      ...options.headers,
    },
    ...options,
  });
  if (!res.ok) throw new Error((await res.json()).message ?? "Request failed");
  return res.json();
}
```

Routes in `App.tsx`: `/login`, `/pos`, `/patients`, `/worklist`, `/reports`, `/admin`. Wrap protected routes in a component that calls `/api/auth/me` and redirects to `/login` on 401. Add a CORS config bean on the server allowing `http://localhost:5173` with credentials during development.

## Part 4 — Build Order (module by module)

Build in exactly this order. Each step produces something testable before you move on.

### Step 1 — Auth
Seed admin via `CommandLineRunner`. Build `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`. Frontend login form → redirect to dashboard. **Done when:** you can log in, refresh the page, and stay logged in (JDBC sessions survive even server restarts).

### Step 2 — Test catalog
`catalog` module: CRUD endpoints for tests and templates, write ops `@PreAuthorize("hasRole('ADMIN')")`. Create 2–3 real templates first, e.g. Fasting Blood Sugar:

```json
[
  { "key": "glucose", "label": "Fasting Glucose", "unit": "mg/dL",
    "refLow": 70, "refHigh": 100, "type": "number" }
]
```

**Done when:** an admin can add a test with a price and template from the UI.

### Step 3 — Patients
`POST /api/patients` (validated DTO), `GET /api/patients?search=` using the repository search query, `GET /api/patients/{id}` returning the full profile + history — and writing an audit log on each view. Generate `patient_no` from a DB sequence. **Done when:** you can register a patient and find them instantly by typing part of their phone number.

### Step 4 — POS billing (the core screen)
The invoice service method is the heart of the system — one transaction, all-or-nothing:

```java
@Service
@RequiredArgsConstructor
public class BillingService {
    private final InvoiceRepository invoices;
    private final InvoiceItemRepository items;
    private final OrderRepository orders;
    private final TestRepository tests;

    @Transactional
    public Invoice createInvoice(CreateInvoiceRequest req, Long userId, Long branchId) {
        List<Test> selected = tests.findAllById(req.testIds());

        BigDecimal subtotal = selected.stream()
            .map(Test::getPrice)
            .reduce(BigDecimal.ZERO, BigDecimal::add);

        Invoice inv = invoices.save(Invoice.of(
            nextInvoiceNo(), branchId, req.patientId(), userId,
            subtotal, req.discount(), req.paymentMethod()));

        for (Test t : selected) {
            InvoiceItem item = items.save(
                InvoiceItem.of(inv.getId(), t.getId(), t.getPrice()));
            orders.save(Order.pendingFor(item.getId()));
        }
        return inv;
    }
}
```

If anything fails mid-way, Spring rolls the whole thing back — no half-created bills, ever. Frontend flow: search patient (auto-fill) or quick-create → click tests → running total → Save & Print. **Printing:** build the dual bill as a JasperReports template (`bill.jrxml`, designed visually in Jaspersoft Studio — free) with two bands: patient copy and lab worksheet copy (blank ruled spaces per test for handwritten results). Serve it as `GET /api/invoices/{id}/pdf` and open it in a new tab for printing. Test on the lab's real printer this week. **Done when:** a returning patient can be billed in under 30 seconds and two copies print correctly.

### Step 5 — Lab worklist + results entry
`GET /api/orders?status=&date=today`, `PATCH /api/orders/{id}/status`, `POST /api/orders/{id}/result`. On result save, the service compares each value to the template's `refLow`/`refHigh` and stores flags:

```java
ObjectNode flags = mapper.createObjectNode();
for (JsonNode field : template.getFields()) {
    String key = field.get("key").asText();
    double v = values.get(key).asDouble();
    if (field.hasNonNull("refHigh") && v > field.get("refHigh").asDouble())
        flags.put(key, "H");
    else if (field.hasNonNull("refLow") && v < field.get("refLow").asDouble())
        flags.put(key, "L");
}
```

Set the order to `COMPLETED`. Frontend: queue table with status buttons; the result form is generated by mapping over the template fields. **Done when:** lab staff can work today's queue start to finish and out-of-range values show H/L automatically.

### Step 6 — Report PDF + delivery
Design `lab-report.jrxml` in Jaspersoft Studio: letterhead, patient block, results table (value / unit / reference range / flag), signature block. `POST /api/reports/{invoiceId}/finalize` fills the template, exports PDF, saves the file, stamps `finalized_at`. Add print + download first; then email (SES SDK, PDF attached, stamp `sent_email_at`) and WhatsApp (Business Cloud API document message, stamp `sent_whatsapp_at`) — only when the patient's consent flags are true. **Done when:** a finished report reaches a patient by print, email, and WhatsApp, and each channel is tracked.

*This completes the MVP (Phase 1). Run the lab on it in parallel with the old process before continuing.*

### Step 7 — Expenses + financial reports
`finance` module: `POST /api/expenses`, `GET /api/finance/daily?date=`, `GET /api/finance/monthly?month=`. Daily = paid invoices grouped by payment method minus expenses; monthly adds profit-by-category via a repository query joining `invoice_items` → `tests.category`. **Done when:** the monthly P&L matches a hand-calculated spot check.

### Step 8 — Dashboard
`GET /api/admin/stats`: today's patient count, revenue, pending orders, plus time-series lists for the charts (Spring Data projection interfaces keep these queries clean). Compute new-vs-returning by whether a patient's first invoice falls in the period. Render with Recharts. **Done when:** the admin opens one page each morning instead of asking staff for numbers.

### Step 9 — Anomaly queue + disease trends
Anomaly queue: `GET /api/admin/anomalies` = recent results with non-empty flags, with an acknowledge action. Disease trends: a nightly `@Scheduled(cron = "0 0 2 * * *")` job aggregates the % of flagged results per test code per month into a small summary table, so the dashboard reads precomputed rows. **Done when:** trends render from aggregated data, not live scans of raw results.

### Step 10 — Hardening pass
Bean Validation on every request DTO (`@NotNull`, `@Positive`, custom validators). Rate-limit login (Bucket4j). Audit every controller for correct role rules — then prove it with MockMvc tests per role. `EXPLAIN ANALYZE` the slow queries and add indexes via a new Flyway migration. Set up the backup cron (Part 5). Do one full restore drill.

```java
@SpringBootTest
@Testcontainers
class BillingFlowTest {

    @Container @ServiceConnection
    static PostgreSQLContainer<?> db = new PostgreSQLContainer<>("postgres:16");

    @Autowired BillingService billing;
    @Autowired OrderRepository orders;

    @Test
    void invoiceCreatesOrdersAtomically() {
        Invoice inv = billing.createInvoice(reqWithTwoTests(), adminId, branchId);
        assertThat(orders.findByInvoiceId(inv.getId())).hasSize(2)
            .allMatch(o -> o.getStatus() == OrderStatus.PENDING);

```

### 6.3 Backups (non-negotiable)

Daily encrypted dump shipped off-site — `/etc/cron.daily/lab-backup`:

```bash
#!/bin/bash
STAMP=$(date +%F)
pg_dump "postgresql://lab:PASS@localhost/labdb" | gzip | \
  gpg --symmetric --batch --passphrase-file /root/.backup-pass \
  > /tmp/labdb-$STAMP.sql.gz.gpg
rclone copy /tmp/labdb-$STAMP.sql.gz.gpg b2:lab-backups/
rm /tmp/labdb-$STAMP.sql.gz.gpg
```

Quarterly: download the latest backup, restore into a scratch database, verify patient counts. Put a recurring calendar reminder on this today.

### 6.4 CI/CD

`.github/workflows/ci.yml`: on every push — `./mvnw verify` (compiles, runs unit + Testcontainers integration tests; GitHub runners have Docker, so Testcontainers just works). On merge to `main` — build the JAR, copy to the server over SSH, restart the service. Take a `pg_dump` in the deploy script immediately before restart; Flyway applies any new migrations at startup.

## Part 7 — Working Practices

- **One feature per branch, merge small, deploy often.** A change that took a day is easy to debug; a change that took three weeks is not.
- **Never develop against production data.** Write a `data.sql`/CommandLineRunner seeder that generates 50 fake patients and a week of invoices so every screen is testable locally.
- **Let the compiler and Flyway be your safety nets.** If it compiles and migrations validate, whole categories of bugs are already impossible — that's why you chose this stack.
- **Write the audit log call at the same time as the feature**, not later. Later never comes.
- **When a Spring error is cryptic**, read the *bottom* of the stack trace first ("Caused by:") — that's almost always the real problem.
- **Show reception staff each screen as you finish it.** Ten minutes of their feedback in week 4 is worth ten hours of rework in week 12.

## Part 8 — Definition of Done (per phase)

| Phase | You are done when… |
|---|---|
| 0 | Login works on a live HTTPS staging URL; `mvn verify` runs green in CI on every push; daily backup cron is live |
| 1 (MVP) | The lab completes one full real day — every patient billed, every result entered, every report printed — without touching the old paper process |
| 2 | ≥ 1 real patient has received a report on WhatsApp and email; monthly P&L matches manual accounts |
| 3 | Dashboard loads in < 2 s; anomaly queue in daily use; a restore drill has been completed successfully |
| 4 | A second branch can be enabled with configuration only — no code changes |
